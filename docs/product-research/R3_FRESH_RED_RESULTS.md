## Что изменено практически

В нашем собственном Go-контуре добавлен независимый слой HTTP-измерений:

- `rca_http_server_requests_total{service,status_class}` — завершённые
  business-запросы; 5xx — серверные ошибки, 4xx считаются отдельно;
- `rca_http_server_request_duration_seconds` — histogram server-side
  длительности, с sum/count и cumulative buckets, а не среднее p95 реплик;
- `/metrics` обслуживается вне trace wrapper и не попадает в эти счётчики;
  health/debug/неизвестные пути тоже не попадают. Для каждого из трёх сервисов
  явно задан один business endpoint. Нет URL/request ID/fault metadata labels;
- используется официальный `prometheus/client_golang v1.25.0`, изолированные
  registry, существующий httpsnoop сохраняет интерфейсы ResponseWriter;
- добавлены отдельный scrape job и [версионированные запросы](../../deploy/acceptance/red-queries.json).
  Request rate — requests/s, error ratio — доля 5xx, latency p95 — seconds.

Это **измерительная часть стенда**, а не доказанное расширение inference
продукта. Старые профили не принимают новые поля, веса их ещё не используют.
Не нужно добавлять обратно все 13 семейств только ради словаря.

## Что проверено по смыслу

Реальный loopback HTTP без TraceProvider сохраняет status 503 и даёт один
5xx-счётчик. Отдельно проверены 200/400/500, неизменность тела/статуса,
равенство denominators counter и histogram count/+Inf, положительная sum,
нулевые счётчики до запросов, 100 параллельных запросов, независимость registry
и отсутствие request ID в labels. Scrape/health/debug не увеличивают счётчики.
Race-проверка telemetry и трёх обработчиков пройдена; `go test ./...` и сборка
трёх команд успешны. Это не доказательство качества ранжирования.

Попытка проверить доступность Docker завершилась `docker.sock: no such file`:
daemon выключен. Настоящий Prometheus сейчас не запускался, его scrape и
PromQL ещё не приняты. Новый capture/fit не имитируется успешным.
Внешний product repository `rca-workbench` не менялся.

## Следующие действия без расширения объёма

1. Поднять только необходимый измерительный контур; подтвердить настоящим
   Prometheus 3/3 scrape, соответствие counter/histogram и единиц, отсутствие
   трафика/отказ источника как отдельные состояния.
2. До новых fault-результатов зарегистрировать небольшой парный пилот:
   нынешнее ядро, сопоставимый вариант с независимыми RED и простая эвристика;
   одни кандидаты/healthy-период, полный и заранее заданный неполный trace-вход.
   Источник/способ обучения challenger сначала должны быть достаточны:
   старые записи не содержат новых полей, их нельзя восстановить задним числом.
3. По добавочной пользе выбрать версию входного контракта и способ интеграции.
   Если эффекта нет, не усложнять продукт; новые веса без этого не продвигать.

Не скачивать ещё несколько корпусов и не запускать grid на старом RE1.
M14 остаётся прежним известным результатом, DOCX вне этой итерации.
