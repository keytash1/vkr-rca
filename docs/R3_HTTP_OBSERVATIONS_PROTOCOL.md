# R3-J: проверка поставки HTTP-фактов, не опыт точности

20.10.2026. До живой проверки зарегистрирован следующий состав. Реализация
на ветке codex/http-observations продукта, исходный main 41245d2.
Резерв R3-I не принят; модель и метод ранжирования не меняются.

## Проверки и предел

1. Самодостаточные адресные проверки: старый профиль без дополнительных queries,
   API/schema, неизменность входного SHA/feature schema/полного рейтинга,
   сохранение snapshot, cache config binding, optional timeout/outage, единицы UI.
2. Записанные фактические Go/Micrometer matrices из R3-G/I пропустить через
   новый декодер. Не новое обращение к закрытому тесту и не пересчёт Accuracy.
3. Запустить только существующий Go-стенд rca-product-acceptance. Получить один
   свежий активный интервал после очистки 30 s lookback, один idle (workload
   остановлен после очистки) и один outage payment (остановлен один свой сервис).
   Ожидания: OBSERVED → NO_ACTIVITY с undefined error/p95 → UNAVAILABLE, не нули.
   Сервисы восстановить в finally; после приёмки остановить только этот стенд.
4. Один сквозной живой запрос API/браузера из актуального исходного продукта,
   сравнение с тем же каноническим входом без optional блока. Исторический
   baseline разрешён только для wiring и с его фактическими предупреждениями,
   не для заявления о качестве. Никакой новой серии воздействий/моделей/LLM.
5. Один полный product regression и проверка состава export/bundle + CI.

Если фактический источник не проходит контракт, зафиксировать конкретный
дефект, исправить только его и повторить затронутую проверку, не всю серию.
Сохранить receipt с исходными границами/статусами. Публиковать только безопасный
сводный результат, источники и веса заморожены. Бюджет реализации до04:15 МСК;
не слить незавершённый UI. DOCX не менять.
