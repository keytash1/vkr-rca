Сначала проверяем контракт и пригодность. Название семейства в статье само
по себе не доказывает, что опубликованы нужные service-level ряды.

- Одна загрузка до 220 MB, до 5 минут; не устанавливать и не запускать чужой код.

- Сначала только directory inventory. Затем по одному нормальному и первому
  лексикографическому аварийному случаю на систему — DISCOVERY_ONLY.
  После выбора зафиксировать их имена до чтения значений; они не входят в test.
- Предел выборочного чтения 100 MB, одного файла 20 MB. Сохранять только
  агрегированный аудит/хэши в Git; внешний архив и сырая телеметрия — ignored cache.

## Что делает источник пригодным

Нужны согласованные времена, отдельное нормальное состояние, известный состав
сервисов независимо от root label и одинаковая нагрузка либо её измерение.
Для CPU/memory/RX/TX — размерность и сохранённые series dimensions; счётчики
преобразуются в rate по каждой series с обработкой reset до суммирования.
Для RED — request/error denominator и latency с указанной статистикой/единицей,
привязанные к сервису. Node CPU, глобальный RPS и span-derived latency не
объявляются независимой сервисной метрикой. Отсутствие — не ноль.
Трассировки должны иметь service/span/parent/time/duration/error и явный scope.
Не выводить здоровый baseline из аварийного будущего и не брать root из имени
файла в матрицу признаков. Параметры инъекции только evaluation metadata.

## Переход от аудита к сравнению

Если вход пригоден, отдельная регистрация до fit фиксирует case ledger,
train/validation/test и группы инъекций, единицы/агрегации, метрики и бюджет.
Один matched challenger: нынешние признаки + реально наблюдаемые RED,
с полными traces и заранее заданным неполным trace-входом, без подбора по test.
Контроли: действующий M13 без переобучения, сравнимый refit без новых полей,
простая метрическая эвристика. Новые признаки не подаются в старые веса.

Если нет необходимых полей, записать точную причину, не создавать фиктивную
совместимость. Допускается один альтернативный источник Eadro (Zenodo 7615394)
после сверки его формата. Не превращать поиск в бесконечный каталог корпусов.
Итог текущего шага — исполнимое решение о входном контракте/пилоте, а не
обязательная новая модель при любых данных.

## Практическое продолжение после directory discovery

В AnoMod SN-архиве нет трёх RED CSV, хотя авторский сборщик содержит их
PromQL. Eadro по опубликованному коду использует семь ресурсных колонок,
а latency извлекает из traces; второй архив не скачивать только ради RED.
Не запускать бессодержательный fit на подменённых измерениях.

Следующий ограниченный шаг — независимые HTTP RED в нашем Go-контуре
gateway/orders/payment: настоящий счётчик завершённых business-запросов по
классу статуса и histogram длительности в секундах, стандартный Prometheus
клиент, отдельный scrape. Health/debug/scrape не входят в нагрузку; нет URL,
request ID или имени воздействия в labels. Метрики работают без tracing.
Смысл error ratio — доля ответов 5xx, latency — server-side completed request.
Это измерительный вход для нового matched опыта, **не новая модель**.
Штатный RCA профиль, 62 признака, веса и результаты ВКР не меняются.

Приёмка этого шага: реальные HTTP статусы/суммы/count/buckets согласованы;
500 учитывается как ошибка, 4xx не становится 5xx; health/debug/scrape не
меняют бизнес-счётчики; parallel запросы безопасны; три сервиса собираются.
Проверка настоящим Prometheus и сбор новых healthy/fault интервалов — до fit,
отдельный зарегистрированный малый пилот, не массовая серия.
