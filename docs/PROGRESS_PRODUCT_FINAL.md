## Дополнительный результат 16 октября: A и API

### Реальная ошибка CPU и её устранение

При чтении сырого Docker stats установлено: `one-shot=true` возвращает нулевой `precpu_stats`. Прежняя формула экспортёра выдавала отношение накопленных счётчиков вместо текущей нагрузки. Теперь CPU вычисляется по двум последовательным снимкам одного контейнера: разность потреблённых наносекунд / разность времени снимков. Первый снимок и сброс счётчика не выдаются за измеренный ноль. Working set учитывает различие `inactive_file`/`total_inactive_file` cgroup v2/v1.

Проверка [local-three-resource-check.json](product-acceptance/local-three-resource-check.json) создана скриптом [verify_acceptance_resources.py](../scripts/verify_acceptance_resources.py): ограниченный 15-секундный CPU-процесс внутри **только нашего gateway**, независимый расчёт по system CPU ticks, сравнение с экспортёром, working set и наличие сетевого потока. Все записанные условия пройдены. Старое здоровое состояние acceptance-1 сохранено как история ошибочного измерения, для действующего профиля больше не используется.

Новая подготовка и проверка: [local-three-run-2/summary.json](product-acceptance/local-three-run-2/summary.json), профиль acceptance-2. Сверка канонических CPU-значений с прямым Prometheus и точное совпадение позиций/баллов live/replay подтверждены. Разметка причины не использовалась.
