# Подключение и версии здорового состояния

Интегратор готовит профиль; инженер выбирает уже подключённую систему и интервал.
Ни в одном обычном запросе инженер не собирает JSON-окно. Discovery помогает
найти метки, но не доказывает полноту инвентаря и не удаляет исчезнувший сервис.

## 1. Проверить смысл источников

Начните с отдельной копии профиля вне активного каталога. Запросы Prometheus
должны возвращать один ряд на логический сервис/момент; реплики агрегируются
по явно проверенной политике. Четыре неизменных семейства:

| Семейство | Каноническая единица | Важное ограничение |
|---|---|---|
| cpu | cores | Не проценты CPU; экспортёр делит приращение CPU-времени на прошедшее время. |
| memory | bytes | Рабочий набор памяти; не безразмерный процент. |
| network | bytes_per_second | Сумма RX и TX после вычисления скорости каждой серии. |
| traffic_rate | bytes_per_second | RX-байты/с, не число HTTP-запросов/с. |

`metrics.semantic_map` описывает каждое семейство: `source_kind` (counter,
gauge, derived), `source_unit`, `canonical_unit`, `transformation`,
`replica_aggregation`, `counter_reset_policy`. Это декларация интегратора,
которую нужно сверить с источником/экспортёром: валидный JSON не доказывает
правильность PromQL. Для counter применяется rate до агрегации; первый отсчёт
CPU/reset не заменяется измеренным нулём.

Для Jaeger новый явный адаптер — `traces.api: jaeger-v3-json`. Он читает
стабильный QueryService v3, проверенный с Jaeger 2.20.0 / jaeger-idl v0.9.0.
`jaeger-http-json` сохраняет прежний адаптер внутреннего API Jaeger UI.
Автоматического переключения после ошибки нет. [Jaeger различает эти API
по гарантиям совместимости](https://www.jaegertracing.io/docs/2.20/architecture/apis/).

У v3 верхняя временная граница исключающая; адаптер прибавляет одну микросекунду
для сохранения включающей границы внутренней схемы. Ответы потока объединяются
по TraceID/SpanID, частичные поиски не затирают друг друга. Противоречащие спаны,
циклы родителей и превышение бюджета отклоняются с неполнотой трассировок.
`searchDepth` не является доказательством полного покрытия; sampling/retention
остаются неизвестными, если установка не предоставляет отдельного подтверждения.

## 2. Получить предложение инвентаря

Все команды из корня установки; файлы результата должны отсутствовать:

```bash
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/profile_onboarding.py \
  --root . inspect --profile drafts/system.json \
  --start 2026-10-17T09:00:00Z --end 2026-10-17T09:05:00Z \
  --output drafts/inspection.json
```

В отчёте — наблюдаемые/неизвестные/отсутствующие имена, покрытие семейств,
предложение объединения со старым инвентарём. Подтвердите алиасы и окружение;
не используйте одинаковые короткие имена из разных проектов без фильтра scope.
Программа не может сама засвидетельствовать, что выбранный период здоровый.

## 3. Подготовить отдельную версию

`artifact_dir` новой версии должен находиться под `deploy/profiles/artifacts/`
и ещё не существовать. Минимум 60 секунд здоровых данных; команды приёмки
дополнительно проверяют успешную нагрузку без известных failed/dropped запросов.

```bash
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/profile_onboarding.py \
  --root . prepare --profile drafts/system.json --confirm-healthy \
  --start 2026-10-17T09:00:00Z --end 2026-10-17T09:05:00Z
```

Создаются здоровые ожидания, метрический контекст и provenance с SHA-256 обоих
файлов и семантического контракта. Модель не обучается. Контракт включает scope
источников, запросы/единицы/шаг, алиасы, множество кандидатов, API трассировок и
источник нагрузки. Заголовок профиля/путь хранения не меняют смысл контракта.

Новые несовместимые настройки с прежним baseline отклоняются. Исторический
baseline без такой привязки не считается новым проверенным: он продолжает
работать с явным `needs_review` и предупреждением. Возраст сам по себе не
доказывает невалидность; релиз/изменение нагрузки требуют проверки интегратора.

## 4. Активация и откат

Команда локальная административная, не HTTP-операция помощника. Для первого
подключения вместо контрольной суммы используется `absent`:

```bash
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/profile_onboarding.py \
  --root . activate --draft drafts/system.json --active deploy/profiles/system.json \
  --expect-active-sha256 absent
```

При замене укажите точную SHA-256 текущего файла. Запись атомарная, конкурирующая
активация отклоняется; прежний профиль сохраняется в `.profile-history` рядом с
активными профилями. Для отката используйте указанный `rollback_profile` как
`--draft` и текущую сумму как expected. Не удаляйте прежние каталоги baseline.
После активации/отката перезапустите процесс диагностики: его модели и ожидания
загружаются один раз. Внешняя передача по новому профилю не включается сама.

## 5. Повторный запрос и поздняя телеметрия

Одинаковый готовый результат переиспользуется в памяти до 15 секунд с отметкой
возраста. Ключ связывает профиль/контракт/baseline/интервал/область доступа.
Есть максимум один расчёт и один присоединившийся одинаковый запрос; остальные
получают 429. Ошибки/предупреждения/неполное покрытие не кэшируются.

«Перечитать источники» (`force_refresh: true`) сбрасывает прежний ответ и
создаёт новый снимок. Неудача перечитывания не возвращает старый ответ как новый.
Уже сохранённая карточка продолжает ссылаться на свой исходный снимок. Удаление
снимка также удаляет его запись в кратком кэше.
