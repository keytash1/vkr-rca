# Программный интерфейс диагностики

API и браузер используют одну реализацию расчёта. Чтение источников выполняется сервером приложения по установленному интегратором профилю; клиент не передаёт URL, PromQL, модель, файловые пути или метку причины.

Машинно-читаемое описание принятой версии доступно на `GET /api/openapi.json` (OpenAPI 3.1). Операции:

- `GET /api/health` — загружена ли модель, какие профили пригодны, какие отклонены при запуске. Это **не** утверждение о доступности источников в данный момент.
- `GET /api/profiles` — список подключённых систем: ID, название, версия и число кандидатов.
- `POST /api/analyze` — получение телеметрии и полный рейтинг по системе и интервалу.
- `GET /api/examples`, `GET /api/results`, формы `example_id`/`incident` — отдельный необязательный исследовательский режим. Не нужны для подключения новой системы; без его файлов список случаев пуст и результаты эксперимента недоступны.

## Вызов из отдельного клиента

Запустите приложение по руководству подключения. Получите ID установленной системы:

```bash
curl --fail http://127.0.0.1:18100/api/profiles
```

Передайте JSON с **тремя** полями: `profile_id`, `start_unix`, `end_unix`. Время — Unix seconds UTC, не миллисекунды и не местная строка без часового пояса. Дополнительные поля не принимаются. Конец позже начала, длительность не более 3600 секунд, конец не в будущем. Для стабильного воспроизведения выбирайте уже завершённый интервал с учётом задержки своей телеметрии.

```bash
curl --fail-with-body http://127.0.0.1:18100/api/analyze \
  -H 'Content-Type: application/json' \
  -d '{"profile_id":"your-system","start_unix":1792148982,"end_unix":1792149022}'
```

Здесь `your-system` и время — шаблон: заменить ID по `/api/profiles` и фактическим интервалом с данными. Этот пример не обещает наличие встроенного проекта или сохранённого инцидента в продуктовой установке.

## Как читать результат

`candidates` содержит весь заданный профилем состав сервисов, с рангами от 1 и `model_score`. Больший балл задаёт более раннюю проверку в рамках **одного** интервала; отрицательный балл допустим. Балл не является вероятностью или доказанным причинным вкладом. `observations` даёт количество, медиану, диапазон и канонические единицы фактических метрик, а также число спанов и спанов с ошибками.

`evidence.coverage.metrics` — доля доступных четырёх семейств; `traces` — признак наличия спанов сервиса; `topology` — признак наличия наблюдаемых рёбер графа. Эти признаки не доказывают полноту всех запросов или временного покрытия. Для live-режима `source_status.metric_point_coverage` отдельно показывает долю **возвращённых query_range-точек** от ожидаемого числа при шаге профиля. Prometheus может переиспользовать последний отсчёт в пределах lookback; это не независимое измерение свежести исходного scrape. Интегратор обязан учитывать scrape/свежесть в запросах и настройке источника.

`source_status` содержит доступность источников, семейства метрик по сервисам, число наблюдений, предупреждения и параметры сбора. Недоступный обязательный метрический источник блокирует рейтинг. Недоступность трассировок отражается как деградация; отсутствие спанов при доступном API показывается отдельно и не считается доказанным отсутствием вызовов. Пропущенные семейства/сервисы не исчезают из списка кандидатов и не становятся измеренным нулём.

`schema_version`, `result_id`, `model_version`, `profile_version`, `feature_schema_sha256`, `baseline_sha256` и `input_sha256` позволяют связать расчёт с конфигурацией и фактическим входом. ID результата уникален для вызова; ID интервала и fingerprint входа могут повторяться. Поздние данные могут изменить повторный живой запрос — детерминизм проверяется на одном сохранённом входе. `timing` разделяет сбор и расчёт; это измерение данного вызова, не SLA.

## Ошибки и ограничения

Ошибки возвращаются JSON-объектом с `code`, безопасным `error`, `fields` и `request_id`. Передавайте ID администратору для поиска в журнале; клиент не должен разбирать текст сообщения, используйте `code`.

| HTTP | Код | Действие |
|---|---|---|
| 400 | INVALID_REQUEST / INVALID_INTERVAL | Исправить поля/время/формат запроса. |
| 404 | PROFILE_UNKNOWN / NOT_FOUND | Получить действующий профиль или проверить путь API. |
| 413 | PAYLOAD_TOO_LARGE | Не передавать тело больше 24 МиБ. Live-запрос значительно меньше. |
| 415 | MEDIA_TYPE_UNSUPPORTED | Использовать application/json. |
| 429 | REQUEST_BUSY | Дождаться завершения текущего анализа, повторить с учётом Retry-After. |
| 502 | TELEMETRY_UNAVAILABLE | Проверить доступность обязательного источника. |
| 502 | TELEMETRY_INVALID | Интегратору проверить метки, агрегацию, формат и достаточность данных. |
| 504 | SOURCE_TIMEOUT | Повторить позже, проверить источник/интервал. |
| 500 | INTERNAL_ERROR | Передать request_id администратору; результат отсутствует. |

Один процесс выполняет один анализ без очереди. На сбор выделен бюджет 120 секунд с проверками между запросами, на один сетевой вызов — до 30 секунд. Отдельный ответ источника ограничен 32 МиБ, суммарные ответы на один сбор — 64 МиБ; поиск Jaeger имеет лимит запросов и разделяет насыщенные интервалы вместо тихого усечения. Это защитные ограничения, не измеренные гарантии времени. Редиректы источников запрещены, чтобы Bearer credentials не пересылались на другой адрес.

Локальная установка слушает loopback. Для сетевой эксплуатации требуется независимо настроенный TLS/auth reverse proxy, политика доступа к телеметрии и ограничения платформы. Внутренний API Jaeger JSON проверяется с конкретной закреплённой версией; он не объявляется стабильным публичным протоколом Jaeger.

## Проверка контракта разработчиком

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python -m unittest discover -s cmd/thesis_demo -p 'test_*.py' -v
```

Проверки включают соответствие OpenAPI/JSON Schema, ошибки, изоляцию профиля, занятость и сохранение зафиксированного ранжирования. Проверка с имитаторами не заменяет записи приёмки фактических источников в `docs/product-acceptance`.
