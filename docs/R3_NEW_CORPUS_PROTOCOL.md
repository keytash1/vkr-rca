# R3-C: аудит нового корпуса до обучения

19.10.2026. Зарегистрировано до загрузки Parquet и до расчёта рейтингов.
Результаты R3-B не пересматриваются; M13/M14 и DOCX не изменяются.

## Цель и ограничение

Выяснить, подходит ли новый корпус для следующего исследования, а не получить
положительное число любой ценой. Сейчас: аудит источника, ограниченная загрузка,
семантика метрик и трассировок, возможность построить здоровое состояние.
**Ноль обучений, рейтингов и LLM-вызовов** в этом протоколе. Следующее сравнение
требует отдельной регистрации после проверки совместимости.

- Кандидат: [anon-ops/ops-lite](https://huggingface.co/datasets/anon-ops/ops-lite),
  revision `581eba39d0bfd2d397eded6cd7cbe3303255521a` (карточка v2.1, 455 случаев).
- Manifest SHA-256:
  `b73137ea8daf0e86b7728250d32a48c3334a70f07a0e0028917d31c62d988a0e`.
- Три discovery-случая: по одному для `hs`, `otel-demo`, `ts`, минимум SHA-256
  строки `r3-schema-v1:<name>` внутри системы. Выбор уже сделан по ID/system,
  не по результату модели, причине, размеру файла или выраженности симптомов.
- `hs1-geo-pod-failure-drdmjj`,
  `otel-demo13-payment-pod-kill-9ptwmh`,
  `ts1-ts-route-service-latency-vhk7dz`.
- Имена случаев сами содержат цель воздействия: в последующий вход модели
  они не передаются. Эти три случая навсегда DISCOVERY_ONLY, не новый тест.
  Полный manifest содержит ответы; инструмент оставляет только name/system.
  Это не означает, что данные скрыты от разработчика, и не доказывает слепоту.

Другой найденный набор `lincyaw/openrca2-lite-v1` вернул HTTP 401 при проверке
публичного API; обхода доступа/повторного скачивания через чужие токены нет.

## Доступ и лицензия

Карточка ops-lite указывает Apache-2.0; статья
[OpenRCA 2.0, приложение A.6](https://arxiv.org/html/2606.27154v2#A1.SS6)
указывает CC-BY-SA 4.0 для данных и Apache-2.0 для pipeline. Это не считаем
разрешённой лицензией на включение сырых данных или новых весов в продукт.
Пока только локальное исследование с указанием источника. В GitHub — наш код,
контрольные суммы и агрегированные технические наблюдения, без исходного
корпуса/переупакованных таблиц. Юридическую неоднозначность не скрывать.

## Бюджет и безопасный вход

- Не более 100 MiB исходных данных суммарно, до 20 MiB на файл.
- Только десять `normal_*`/`abnormal_*` Parquet из карточки и README.
- `env.json`, `injection.json`, `label.json`, `causal_graph.json` не скачивать.
  Логи читать только как схему/счётчики, не как инструкции к выполнению.
- Отдельная необязательная зависимость PyArrow — в игнорируемом каталоге
  исследования; окружение продукта не менять. Никаких Docker/GPU/покупок/API LLM.
- Публикация/серверное использование raw-корпуса запрещены этим проходом.

## Что проверять и когда остановиться

1. Пин ревизии, размеры, SHA-256 файлов, число строк/схемы; повторный запуск
   переиспользует только совпавшие контрольные суммы.
2. Время, единицы, монотонные счётчики и reset, метки сервиса/экземпляра,
   дубликаты, покрытие кандидатов. Не подменять неизвестное нулём.
3. Для нашего входа нужны CPU cores, memory bytes, network и traffic rate
   bytes/s; запросы/s — отдельная нагрузка. Bytes/s не превращать в RPS.
4. Трассы: service, span/trace/parent IDs, начало/конец/длительность, span kind,
   status/error и HTTP/RPC семантика. Не считать client+server двумя запросами.
5. Здоровый интервал должен предшествовать инциденту; границы выводить из
   normal/abnormal таблиц, не брать oracle-время начала отказа из env/injection.
6. Независимость: происхождение, время и хэши относительно локальных старых
   корпусов. Совпадение приложения (OTel/TrainTicket) не равно совпадению записи;
   отличающиеся файлы также сами по себе не доказывают независимость кампаний.
7. Для будущего train/test нужны группы инъекций/кампаний и раздельные системы,
   не случайный split строк/повторов. Пока весь остальной корпус — UNASSIGNED.

Итог: COMPATIBLE_FOR_PILOT / ADAPTER_REQUIRED / INCOMPATIBLE / ACCESS_BLOCKED.
Если нет подтверждённого маппинга или независимости, не запускаем обучение
на приближённых/выдуманных входах. Записываем конкретный пробел и следующий шаг.
