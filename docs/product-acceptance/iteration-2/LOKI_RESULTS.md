# Настоящий Loki: результат и решение о продвижении

19.10.2026. [Предварительный протокол](LOKI_PILOT_PROTOCOL.md).

## Вердикт

`PROMOTED_BOUNDED_OPTIONAL_CONTEXT`: достаточно инженерного сигнала для
ограниченной функции. Не «новая доказанная причина», не прирост Accuracy,
не подтверждённое ускорение инженера и не улучшенная LLM.

## Что было настоящим

Loki 3.7.8, официальный ARM64 binary, loopback HTTP 18310/gRPC 18311,
собственный filesystem. SHA-256 release asset:
`95d830437482aba989a7d7a65be3c618a67a6e46f6e614544cc4b9ce09f499a1`.
Источник установки: [официальный release](https://github.com/grafana/loki/releases/tag/v3.7.8),
[руководство](https://grafana.com/docs/loki/latest/setup/install/local/).
Встроенная аналитика выключена, ни Docker, ни системная служба не запускались.

Учебный сервис выполнял реальные HTTP-операции: dependency вернула 403,
соединение к неслушающему порту было отклонено, ожидание ответа истекло.
Журнал формировался по фактическому исключению, не по названию сценария.
Записи отправлены push API и считаны настоящим query_range. Controller truth
лежит отдельно и в Loki не отправлялась. Это не корпоративная система.

## Содержательная парная оценка

| Случаи | Без контекста | Что добавлено | Вывод |
|---|---|---|---|
| p01–p02, отказ доступа | Внешний 503, число запросов, длительности | HTTPError + фактический 403 зависимости | Есть основание проверить права/настройки доступа вместо угадывания по общему 503 |
| p03–p04, отказ соединения | Такой же внешний 503; задержка сама не раскрывает исключение | ConnectionRefusedError | Есть основание проверить адрес, порт и слушающий процесс |
| p05–p06, таймаут | 503 и более длительное ожидание уже подсказывают timeout | TimeoutError | Подтверждает вид операции; не засчитываем безусловный дополнительный выигрыш |
| p07, посторонний релиз | Контроль не относится к выбранному сервису | Ни одной записи из чужого scope | Не объявлен причиной |
| p08, нет записи | Нет подтверждающих сведений | available с 0 записей и неизвестным покрытием | Не объявлено здоровьем |
| p09, лимит | Сокращённая выдача | truncated с 1 записью | Неполнота явная |
| p10, источник недоступен | Контекст получить нельзя | unavailable | Не заменено нормальным нулём |

Во всех шести отказах по три записи. Выбранные поля и SHA-256 совпали
с исходными записями приложения; точный end-exclusive запрос на наносекундной
границе не включил запись. Количества здесь — сверка полноты конкретного
контрактного случая, не оценка вероятности диагноза. Полные данные:
[итоговая квитанция](loki-live-final/receipt.json),
[журнал приложения](loki-live-final/application-ledger.json).

Достаточность: для отказов доступа и соединения появился различающий
проверяемый факт и конкретная следующая проверка; контрольные ситуации
не сформировали автоматическую причину. Это именно заранее заданный барьер
продвижения, а не статистическое превосходство на 10 случаях.

## Ошибки измерительного скрипта не скрыты

Первая попытка остановлена на p03: padding начала 5 ms захватил запись
предыдущего случая. Вторая — на p08: два немедленных чтения часов дали
нулевую длительность контроля. Это ошибки инструмента опыта, не отказы Loki.
У первой сохранился снимок 18 записей, у второй — 36 записей двух попыток;
полных парных выводов по ним нет. Они не входят как успешные опыты.
Исправлены только реальные границы и гарантированное сохранение исходов.
Третий проход — полный и сохранённый. Никакого подбора модели/ответов LLM.
Файлы неудач: `loki-live-1/failed-attempt-source-records.json`,
`loki-live-2/failed-attempt-source-records.json`.

## Доведённая продуктовая граница

Необязательный операторский `context` в профиле: один Loki и до 20 сервисов,
до 100 записей суммарно и 10 s ожидания на batch. Инженер по-прежнему выбирает
систему/интервал; каталог и снимок дополняются независимыми фактами.
Отказ, усечение и недоступность projection не ломают ранжирование и не
маскируются кэшем полного успешного ответа. Вход и веса модели не менялись.

По умолчанию контекст локальный. `assistant_categories=true` отдельно разрешает
только фиксированные категории/количества, с прежним проектным разрешением
передачи агрегатов. Ни тело, ни класс исключения, ни версия/адрес/хеш не уходят
в провайдер. Инструменты получают тот же разрешённый снимок без нового
сетевого доступа. Новых вызовов провайдера — ноль.

Одна версия или HTTP 200 сами по себе не классифицируются как ошибка;
неизвестный класс реального исключения получает только OTHER_ERROR. Нет
свободного семантического угадывания причины по произвольной строке.

Продуктовый HTTP-путь проверен с настоящим Loki и **искусственными** метриками/
трассами: рейтинг и SHA входа совпали с запросом без context, снимок сохранил
новые факты; OpenAPI и категория для инструментов согласованы.
Полные квитанции: [результат](loki-product/analysis.json),
[каталог](loki-product/catalog.json), [проекция](loki-product/assistant-category-projection.json).

Затем настоящий Loki остановлен. Повторный HTTP-запрос вернул 200, тот же
рейтинг и вход; новый контекст — unavailable, кэш старого ответа не использован.
Старый снимок продолжает содержать прежние факты. Квитанция:
[отказ источника](loki-product/source-down.json). Компактный UI проверен
в браузере: [снимок](loki-product/context-ui.png). Временный сервер — только
учебная приёмка, не изменение прежних пользовательских подключений.

## Ограничения переноса

Только структурированные разрешённые поля, только установленный инвентарь;
чужие/ненастроенные сервисы не ищутся автоматически. Выборка ограничена,
sampling/retention/delivery неизвестны, время Loki не равно доказанному времени
события. Классификация — фиксированные наблюдаемые категории, не обученная
причинная модель. В новой компании остаётся проверка меток, часов, прав,
происхождения и возможности попадания секретов в выбранные поля.
Незнакомые форматы не интерпретируются свободным LLM-текстом.
