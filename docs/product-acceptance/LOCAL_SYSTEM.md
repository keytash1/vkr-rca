# Приёмочное подключение A

Назначение — проверить интеграцию переносимого приложения с настоящими источниками на собственной известной системе до подключения внешнего проекта B. Качество ранжирования по размеченным отказам в этом протоколе не оценивается.

Система: gateway, orders, payment из исходников `vkr-rca`; HTTP-вызов обработки заказа проходит через три сервиса. Изолированный Compose-проект — `rca-product-acceptance`; сторонние проекты на машине не изменяются.

Источники: Prometheus 2.54.1 и Jaeger 2.20.0, образы закреплены digest в `deploy/acceptance/compose.yml`. Используемый контракт Jaeger — HTTP JSON `/api/traces`, ограничение внутреннего API принято для указанной проверяемой версии; нет заявления о совместимости с любой версией Jaeger.

Метрики Docker API собираются по instance и агрегируются PromQL по service. CPU — число ядер по двум последовательным снимкам; память — working set в байтах; network — RX+TX, traffic_rate — RX, обе rate за 5 секунд в байтах/с. Это исходный контракт `docs/m12-adapter-contract.md` и `scripts/m13/run.py`. Нагрузчик публикует фактический счётчик начатых запросов; постоянное значение RPS во вход не подставляется. Действующий профиль — `deploy/acceptance/profiles/local-three.json`, acceptance-4; предыдущие версии сохранены в протоколах для аудита исправлений.

Критерии: пригодное покрытие здорового интервала всех четырёх семейств и спаны каждого кандидата, совпадение значений всех семейств с прямыми Prometheus-запросами, включение TraceID/SpanID из отдельного поиска каждого сервиса, полный рейтинг, точное совпадение replay/live на завершённом интервале, браузерный путь и отказы. Поиск не предполагает единого trace context через gateway. Здоровый период проходит при нормальной нагрузке и без включённых воздействий.

Подготовка и проверка:

```bash
docker compose -f deploy/acceptance/compose.yml up -d --build
# После появления не менее четырёх минут телеметрии:
.venv/bin/python scripts/accept_live_profile.py \
  --profile deploy/acceptance/profiles/local-three.json \
  --output docs/product-acceptance/local-three-run-1
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/server.py \
  --root . --profiles-dir deploy/acceptance/profiles --port 18218
```

Команды требуют доступа к локальному Docker и HTTP-сокетам. Каталог результата создаётся без перезаписи, базовое состояние также не заменяется молча. Фактический статус определяется `summary.json` и записью браузерной проверки, а не наличием этой инструкции.
