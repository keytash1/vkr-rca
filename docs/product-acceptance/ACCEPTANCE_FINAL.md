## Инженерный вывод

Приложение подключается к системе через установленный профиль и её здоровое базовое состояние. Инженер выбирает систему и интервал в браузере; сбор и преобразование выполняются приложением, ручной JSON не требуется. Основной путь проверен на собственных трёх Go-сервисах и внешнем Java/Spring Petclinic, с фактическими Prometheus 2.54.1 и Jaeger 2.20.0. Это два отдельных подключения, не имитаторы API.

Установка из публичного GitHub в новый каталог и новый Python venv пройдена. Минимальный профильный комплект затем установлен в ещё один venv и выполнил реальный браузерный запрос без исследовательского корпуса. Продуктовый расчёт сохраняет прежний результат исследовательской модели. Нет основания утверждать универсальную точность, корпоративную эксплуатационную готовность или подтверждённое пользователем удобство: отзыв автора по его просьбе оставлен на финальную приёмку после отчёта.

## Найденные дефекты и повторная приёмка

### Контейнерная поставка

`deploy/product/Dockerfile` собирает только API/UI, вычислительный код и 14 необходимых артефактов. Нет baseline чужой системы, корпуса, разметки, M14 runtime и CUDA/NCCL. Linux использует CPU-only пакет XGBoost 3.2.0. `container-runtime-regression.json`: все 50 отдельно смонтированных контрольных входов на Linux ARM64/Python 3.12.15 дали точно прежние ранги и баллы. `pip check` не нашёл нарушений. Рабочий UID — 10001:10001, ФС только на чтение, capabilities удалены, порт опубликован только на loopback.

Базовое состояние Petclinic создано заново внутри контейнера, из реальных источников, за 14:19:32–14:21:42 UTC. `container-petclinic/summary.json`: отдельный HTTP-клиент запросил 14:28:12–14:30:12 UTC; все четыре кандидата, баллы и наблюдения совпали с нативным расчётом того же канонического входа. Совпал SHA-256 входа `fdbe13efeeb2d00919e5aefc542bc2dbefdc0a3d2e63ecce6252aafeae0e6cc5`. Измерены сбор 0,3336 с, расчёт 0,0743 с, полный ответ 0,4079 с. Это один запрос, не SLA. Другой пятиминутный запрос выполнен из браузера (`ui-final/container-result.jpg`, интервал указан на экране); его показатели не подменяются значениями HTTP-прогона.

Во время длительной работы in-memory Jaeger B завершился из-за OOM. Ограничены `max_traces=4000` и Go-память, перезапущены только два Jaeger собственных стендов; подключение повторено после восстановления. Старые спаны в памяти утрачены, сохранённые протоколы не изменены. Число трасс не гарантирует длительность хранения: штатному источнику организации нужна своя проверенная retention policy. Ошибка первой Compose-команды (некавыченная строка tmpfs разделилась по запятым) исправлена до запуска; конфигурация проверяется в CI. Ничто из этого не считается новым научным опытом или поводом менять модель.

Сначала найдены и исправлены: усреднение CPU от начала жизни контейнера, потеря изолированных трасс при поиске только по gateway, неправильное разделение RX/TX вместо исходных сетевых семейств, лишние модельные зависимости и скрытая импортная зависимость `schema.py` автономного пакета. Ранние записи не удалены и не выданы за окончательную приёмку. Матрица и действующие версии указаны в журнале.

В первых попытках чистой локальной установки A отсутствовал счётчик dropped старого нагрузчика, B имел неудачные запросы выбранного периода. Оба прогона отклонены до подготовки baseline. Проверка отсутствующих/NaN/отрицательных счётчиков исправлена на явную ошибку; после обновления A выбран новый полный здоровый период. Результат ранжирования не использовался для отбора интервала либо замены проекта B.

## Качество метода и открытая пользовательская приёмка

На исходном независимом опыте Astronomy Shop остаются 50 случаев, Accuracy@1=0,50, Accuracy@3=0,70, Accuracy@5=0,78, MRR=0,629955. Модель не донастраивалась по этим данным или по новым подключениям. Инженерная успешность A/B не добавляет случаев в знаменатель этих метрик и не доказывает правильность первого кандидата в здоровом интервале.

Автор проверит удобство в самом конце, после готовности документов; до его ответа P09 не обозначается полностью закрытым. Текущий пользовательский сервер — `127.0.0.1:18218`; изолированный комплект был проверен на `18219`. Для компаний требуется отдельная настройка защищённого reverse proxy, доступа к источникам и эксплуатационных требований. Встроенный сервер имеет loopback-режим, не собственную SSO/TLS/HA-инфраструктуру. Новый самостоятельный репозиторий требует выбора имени и лицензии и не создаётся без этой развилки; принятый код уже опубликован в `vkr-rca`.
