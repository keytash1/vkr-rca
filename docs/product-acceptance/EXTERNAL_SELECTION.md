# Выбор внешнего подключения B

Дата решения: 16 октября 2026 года. Роль данных: **инженерная приёмка подключения**, не новый опыт точности, не обучение и не выбор гиперпараметров. Профиль выбирается по API, инструментированию, лицензии и ресурсам до получения рейтингов. Результаты ранжирования не используются для замены объекта приёмки на более выгодный.

В checkout `8f4a7c32aa123fe9b743cb38cee58e8f1f85caed` отсутствует файл LICENSE, Java-agent скачивается по latest; полный штатный стек требует OpenSearch. Не выбран для основной воспроизводимой приёмки; исходники не включаются в поставку нашего продукта. |

## Происхождение и состав

- Код для изучения: https://github.com/spring-petclinic/spring-petclinic-microservices , commit `1d76b00d683e86b62867a6bf59530f8ab301244f`.
- Штатная конфигурация: https://github.com/spring-petclinic/spring-petclinic-microservices-config , commit `323993ce2519c6d02df63e08bf4458d123d3b611`.
- Для запуска используются **опубликованные авторами образы**, перечисленные их Compose, с точными digests в [compose.yml](../../deploy/acceptance/petclinic/compose.yml). Их бинарный состав идентифицируется digest; совпадение сборки с указанным исходным commit не утверждается без соответствующего provenance. По умолчанию upstream использует mutable latest — здесь digest зафиксирован до выполнения приёмки.
- Четыре диагностических кандидата: `api-gateway`, `customers-service`, `visits-service`, `vets-service`. Config/discovery — явно вынесенная обслуживающая инфраструктура, не скрыто потерянные кандидаты. Базы HSQLDB встроены в прикладные процессы согласно штатному профилю.
- GenAI/платные LLM-вызовы не запускаются, ключи пользователя не требуются; также не требуются admin UI/Grafana. Прикладная логика не переписывается. Config Server получает зафиксированные native-файлы вместо плавающей Git-ветки.
- Штатный Zipkin-экспорт принимает настоящий OpenTelemetry Collector и передаёт в Jaeger 2.20.0. Это конфигурация наблюдаемости установки, не новая модель и не подмена спанов. Продукт по-прежнему читает Jaeger/Prometheus через свои общие адаптеры.
- CPU, память и сетевые счётчики измеряются исправленным Docker-экспортёром только у четырёх помеченных контейнеров. Нагрузка — реальные GET-операции владельцев/визитов/ветеринаров; их фактическая интенсивность считывается из счётчиков нагрузчика, не задаётся константой модели.
- Окружение — отдельный `rca-petclinic-acceptance`, порты только loopback 18880/19687/19991. ReBAC не изменяется.

## Критерий приёмки

Сначала подтвердить нормальную обработку запросов, четыре семейства метрик каждого кандидата, имена и связи реальных спанов; затем снять здоровый интервал без старта/прогрева, проверить профиль, подготовить отдельное базовое состояние. После этого выполнить запрос через API и браузер, сверить канонические наблюдения с источниками и replay того же сохранённого входа. Полный рейтинг содержит все четыре кандидата. Ни успешный запуск Compose, ни визуально правдоподобный Top-1 не являются основанием объявить этап выполненным.

## Найденные проблемы и принятые исправления

1. `petclinic-run-1` отклонён: выбранный период ещё включал ошибки регистрации/прогрева. Критерий нормальной нагрузки не ослаблялся; `workload-health.json` сохраняет причину отказа.
2. Первоначальный поиск только по gateway терял отдельные трассы visits-service. Прямой поиск Jaeger по visits-service находил их, поэтому API-success/replay-match ранних прогонов сами по себе не означали принятую полноту. Теперь ищутся все кандидаты и алиасы, TraceID дедуплицируются; для здорового состояния спаны нужны у каждого кандидата. Метод не получает выдуманных межсервисных рёбер, если propagation разорвана.
3. В ранних приёмочных профилях сетевые семейства ошибочно разделялись на RX/TX. Исправлены на исходный контракт: network=RX+TX, traffic_rate=RX, rate 5s. Действующая версия Petclinic — acceptance-3, соответствующие артефакты созданы заново. Это исправление совместимости, не подбор по качеству ранжирования.
4. Итоговые API-сверки: `petclinic-run-4` и усиленный `petclinic-run-5`. Последний проверяет все четыре семейства и присутствие прямых TraceID/SpanID каждого кандидата, а не только доступность Jaeger и совпадение CPU. Реальные отключения источников — `petclinic-source-failures.json`. Отдельная запись браузерного прохода требуется для закрытия UI-части; внешний пользовательский отзыв пока не получен.
