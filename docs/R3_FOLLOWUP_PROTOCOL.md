19.10.2026, до новых случаев и новых ответов. Исходный `R3_PROTOCOL.md`
не меняется: v2 остановлен как TECHNICAL_INCONCLUSIVE, не успешный опыт.
Шесть ответов C0 ещё не использованы для изменения prompt/подбора решений.
Четыре C1 не дошли до провайдера из-за отсутствия словаря; один C0 прерван,
удалённый исход неизвестен. Верхняя оценка уже потраченных generation attempts — 7.

Исправление: worker наследует только выбранный оператором путь публичного
словаря, включая путь Docker image. Словарь отдельно загружен и SHA проверен.
Модель, prompt, схема, вопрос, признаки и ранжирование не изменяются.

Новый малый development-срез: **4 свежих случая / 8 запросов максимум** —
отказ доступа 403, connection refusal, timeout .20 s и 503 с недоступным
контекстом. По три HTTP-запроса, новая сессия; тот же ограниченный сборщик.
Это не новые независимые механизмы/проект и не замена исходного восьмислучайного
знаменателя. Верхняя общая оценка обеих серий: 7 + 8 = 15 generation attempts,
меньше первоначального лимита 16. Никаких повторов исходных 11 начатых задач.

Перед вызовами — локальный preflight **всех восьми** входов штатным способом
и проверка verified tokenizer (без inference). Не прошёл один — не запускать
ни один. Ограничения прежние: 1 model call, 60 s, 12000/3000 tokens; нет tools,
repair, покупок или запасного провайдера. Любой runtime/preflight/provider отказ
останавливает серию после сохранения исхода, без ручной гонки на прерывание.

Рубрика прежняя, primary теперь только описательная: пары по трём механизмам
и один контроль неполноты. Даже 3/3 не доказывают выполнение исходного барьера
14/16 или независимое превосходство. Можно заключить, даёт ли категория
конкретную проверку и корректно ли используется в этих трёх примерах.

пользу данных интеллектуальному рассуждению LLM. Не увеличивать этот срез.
