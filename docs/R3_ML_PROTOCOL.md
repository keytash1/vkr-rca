# R3-B — ограниченная проверка улучшения ранжирования

19.10.2026. Зарегистрировано до нового расчёта признаков и OOF-оценки.
Поручение: продолжить весь обоснованный продуктовый план, не ограничиваться
декларацией одной гипотезы. Этот протокол закрывает ближайший вычислительный
барьер; положительный screening не разрешает немедленную замену продукта.

## Отбор направлений

| Направление | Решение до расчёта | Основание |
|---|---|---|
| Временная форма наблюдений | Проверить matched screening | Сохранены секунды метрик и временные метки спанов; действующие агрегаты в основном теряют порядок |
| Другой диапазон здоровой нагрузки | Не дообучать по инцидентам | Нужен новый здоровый сбор при новых нагрузках; существующие 6/9 RPS уже использованы |
| Исчезновение сервиса и топология | Сначала проверить наличие/покрытие, не дублировать признаки | В M13 уже есть блок disappearance и propagation; новая сложность без нового сигнала не обоснована |
| Логи как признаки ML | Пока не включать | Loki-пилот не является новым размеченным train/test; category может зависеть от контроллера воздействия |
| GNN, LLM вместо ранжировщика | Не добавлять в этот проход | Сначала проверить простое дополнение на тех же данных и простую эвристику |
| Новый внешний корпус | Проверить источники и совместимость, не скачать всё | RE2/RE3/M12/M14 уже использованы как test; новая упаковка тех же данных не делает их новым тестом |

## Данные и независимость

Единственный разрешённый screening-корпус — локальный M13 Social Network:
120 инцидентов, 60 групп повторов. Теперь его роль USED_DEVELOPMENT, не новый
независимый тест. Проверить каждый raw SHA, index/truth seals, полный знаменатель,
временные границы, полноту кандидатов и существование здорового сбора.
M14, M12, RE2/RE3 и ответы LLM не читать для подбора и не использовать в fit.

Healthy-only M13 baseline фиксирован по отдельному сбору до инцидентов;
это заранее заданная калибровка данного стенда, не обучение по validation.
M10C/M11 frozen context допустим условно: manifest подтверждает обучение на
RE1 до появления M13. Нового fit этих зависимостей нет. Следовательно,
screening оценивает условную процедуру с фиксированной здоровой калибровкой
и внешним pretrained context, не полностью независимый перенос.

Frozen M13 обучен на всех 120 случаях; его результаты здесь in-sample и
**не являются честной baseline для OOF-challenger**. Главный контроль — та же
процедура LambdaMART с прежними 63 признаками, переобученная в тех же folds.
Сохранить текущее frozen поведение только как справочную производственную
точку, без использования для promotion.

## Гипотеза и точный вариант

Десять дополнительных service-invariant признаков:
ранний/поздний q90 абсолютного метрического остатка и их разность;
время первого наблюдаемого отклонения >=3 и маска его наличия;
ранняя/поздняя доля ошибочных спанов и их разность;
время первого ошибочного спана и маска его наличия.
Ранняя/поздняя части — первая/последняя треть выбранного интервала.
Время нормировано по границам интервала, не является временем инъекции
или доказанным порядком причин. UNKNOWN/no spans не превращаются в доказанное
отсутствие вызовов: маски и исходные coverage-признаки остаются.

Вычисление получает только canonical telemetry и фиксированный baseline.
Root, fault, system, incident_id, workload_result и команды воздействия
не передаются feature extractor. Service identity — join key, не число модели.
Перестановка входных списков и взаимно однозначное переименование сервисов
должны сохранять значения соответствующих признаков.

Контроли: прежняя метрическая эвристика и простая временная эвристика:
сначала более раннее наблюдаемое отклонение, при равенстве больший metric shift;
при отсутствии отклонения сервис остаётся в полном рейтинге.

## Разбиение и бюджет

3 детерминированных grouped folds по полной группе
system/root/fault/workload/intensity; оба повтора вместе. Два seed: 20261019,
20261020. Две конфигурации: прежние 63 признака и те же +10 временных.
Параметры общие: depth 3, eta .08, 24 rounds, rank:ndcg, ndcg@3,
topk pairs 5, min_child_weight 2, subsample/colsample .8, nthread 2.
Итого 12 ranking fits. Перебора параметров и rerun ради удачного seed нет.
Максимум 20 минут процесса, 50 MiB новых артефактов. Без Docker/GPU/LLM.

Primary — MRR полного OOF-знаменателя. Вторичные — AC@1/3/5, coverage,
срезы по fault/root/workload, время вычисления. Средние scores двух seed
образуют один парный OOF-рейтинг. Сохранить также результаты каждого seed.
Парные 95% cluster bootstrap CI, 2000 resamples; это development-screening,
не unbiased estimate выбранной по нему процедуры.

Перспективным считать только вариант с delta MRR >=.02, положительной нижней
границей CI, без потери AC@3/5 более .02 и без потери AC@1 любого fault >.10.
При отрицательном результате — REJECTED_FOR_PROMOTION, остановить эту линию.
При положительном — NEEDS_FRESH_TEST, не менять продукт до нового независимого
корпуса/кампании с заранее зафиксированными критериями. Нельзя назвать старый
M14 новым hidden test, докачать его репак или сравнить OOF с in-sample как успех.

## Источники и поставка

Split до обучаемой подготовки: [scikit-learn](https://scikit-learn.org/stable/common_pitfalls.html).
Группа query в LambdaMART — один инцидент, не произвольная строка сервиса:
[XGBoost 3.2](https://xgboost.readthedocs.io/en/release_3.2.0/tutorials/learning_to_rank.html).
[RCAEval](https://github.com/phamquiluan/RCAEval) публикует те же RE1/2/3;
повторная загрузка не устраняет историю использования.
[OpenRCA](https://github.com/microsoft/OpenRCA) требует отдельного адаптера и
заявляет рекомендованные 80 GB диска/32 GB RAM; не запускается автоматически.

Выход — отдельные audit/registration/results и содержательный вывод.
Исторические веса, seals, исходный M14 и оба DOCX не менять. Новое runtime-
изменение поставляется только после подтверждения пользы и проверки отката.
