# Журнал R3

19.10.2026. Запущена одна линия R3-A по явному поручению пользователя.
Отчёт, веса M13 и результаты M14 не изменяются.

1. Сверены актуальный handoff, чистый продукт bb910cd и существующее разрешённое
   локальное подключение. Auth-содержимое в чат/артефакты не читалось.
2. До данных/генераций зарегистрирован `R3_PROTOCOL.md`: 8 свежих случаев,
   16 API-попыток максимум, без повторов, fixed prompt/model и semantic rubric.
3. Собраны восемь новых случаев в `product-research/r3-context-v2`. Измерены
   запросы, статусы, caller-side server/client spans и журналы приложения;
   серверные спаны зависимости не выдумываются. Ресурсные ряды и healthy
   baseline искусственные. Frozen M13 применён без обучения к каждому входу.
   Парные не-контекстные факты/ранг совпадают; outbound проходит штатный privacy
   projector. Исходные исключения, localhost URL и controller truth не выходят.
4. Неудачи до генераций: первый запуск запретил локальный socket; пустой каталог
   убран. Затем сборщик передал None вместо пустой строки parent_span_id,
   validator отклонил до ранжирования/генерации. `r3-context-v1/healthy-fixture.json`
   сохранён как след незавершённого сбора; новый v2 — отдельная сессия.
5. Перед первым вызовом записаны protocol/prompt/input hashes, полный порядок
   16 задач и data ledger. Старт генераций; повторов/repair не будет.

## Итог ограниченного прохода

6. Исходная серия остановлена: 6 готовых C0, 4 C1 preflight-отказа без API,
   1 прерванный C0 с неизвестным удалённым исходом. Пять задач не начинались.
   Исходный протокол не переписан; `r3-context-v2/STOPPED.json` запрещает resume.
7. Исправлено наследование публичного tokenizer cache в продукте. В локальном
   опыте словарь не был прогрет; кроме этого найден самостоятельный дефект:
   worker игнорировал настроенный Docker cache. Только выбранная cache-настройка
   передаётся, остальные переменные/секреты по-прежнему отсечены. SHA и fallback
   не ослаблены. 146 Python-тестов прошли, contracts/image CI зелёные.
   [PR #3](https://github.com/keytash1/rca-workbench/pull/3) объединён,
   локальный/remote main продукта `aea24f5`.
8. До новых ответов зарегистрирован `R3_FOLLOWUP_PROTOCOL.md`: 4 свежих случая,
   8 попыток, preflight всех входов до первой генерации. Все 8 ответов готовы,
   без повторов. Обе серии вместе — 14 известных + максимум 1 неизвестная
   generation attempt, в пределах первоначального лимита 16. Новых покупок нет.
9. Содержательно: permission и timeout дают полезное уточнение; в одном
   запланированном connection-refusal фактически получен timeout — это
   невалидная постановка воздействия, не успех и не ошибка LLM. Контроль
   недоступного журнала не превращён в уверенный диагноз/здоровый ноль.
   Детерминированные UI-проверки уже дают похожий следующий шаг: независимая
   добавочная польза LLM не доказана. Полный разбор —
   [R3_RESULTS.md](product-research/R3_RESULTS.md).
10. Этот проход завершён без обучения/замены ML. Следующий — отдельная
    ML-гипотеза и аудит нового корпуса по handoff; автоматического продолжения
    LLM-прогонов нет. V54 SHA совпал с исходным, DOCX/диаграммы не изменены.
11. Уже после фиксации всех результатов в ba1f8ed исправлен исследовательский
    сборщик: capture сохраняется до oracle; mismatch фактического класса/кода
    останавливает подготовку до ML/LLM. Четыре локальных проверки прошли,
    включая настоящий ConnectionRefusedError после закрытия локального порта.
    Новых генераций нет. Продуктовый main aea24f5, послесливочный CI успешен.
