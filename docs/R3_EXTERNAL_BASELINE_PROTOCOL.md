# R3-L — внешний алгоритм на тех же случаях

Дата регистрации: 20.10.2026. До запуска новых предсказаний BARO.

## Зачем и что именно проверяется

В итоговом опыте на Astronomy Shop сравниваются наш зафиксированный ансамбль,
предыдущий собственный ранжировщик, метрическая эвристика и случайный порядок.
Это не сравнение финального ансамбля с внешними готовыми алгоритмами.
Исторические прогоны TraceRCA/BARO относятся к другим версиям и наборам.

Добавить один воспроизводимый внешний метрический ориентир — BARO из уже
использованного RCAEval, commit `405c8fd24071af41ceb4b3aabb451e5e3e15d6c6`.
Источник: https://github.com/phamquiluan/RCAEval/tree/405c8fd24071af41ceb4b3aabb451e5e3e15d6c6

Вызывается неизменённая функция `RCAEval.e2e.baro.baro`, не собственный
RobustScaler-двойник. Из BARO используется этап локализации после известного
начала диагностического окна; обнаружение момента инцидента не сравнивается.
Это алгоритмическая реализация RCAEval, не испытание коммерческой платформы.

## Статус данных и защита от подгонки

- Все исходные 50 окон Astronomy Shop, все 12 кандидатов, исходный здоровый
  период 900 секунд. Никаких новых воздействий, загрузок, обучения или LLM.
- Набор уже USED_TEST, результаты и метки известны. Это дополнительное
  **post-hoc сравнение**, не новый скрытый тест и не новая оценка переноса.
- Собственные сохранённые рейтинги не пересчитываются и не изменяются.
- Параметры BARO не подбираются. Dataset=`astronomy-shop`, то есть общий
  preprocessing без правил для OB/TT; `dk_select_useful=False`, как по умолчанию.
- В BARO попадают только исходные четыре метрических семейства. Он не получает
  разметку причины, тип воздействия, имя файла, ID инцидента или наши рейтинги.
- Метки читаются только отдельной командой оценки после записи predictions.
- Выбор метода сделан по доступности корректного входа и прошлой воспроизводимости,
  не по результатам на этих 50 случаях. Не добавлять методы до получения победы.

## Адаптация без изменения алгоритма

Metric records преобразуются в DataFrame: `time`, `c0000_cpu`, ...;
код кандидата определяется позицией в сохранённом списке, а не разметкой.
Все исходные значения и единицы сохраняются: CPU cores, память bytes,
RX/TX bytes/s. `traffic_rate` здесь историческое имя TX, НЕ request rate.
Одинаковые временные точки объединяются по точному timestamp, без ресемплинга,
интерполяции, заполнения отсутствующих значений или отбора по качеству ответа.
Таблицы healthy/incident должны быть полными; несоответствие — явный отказ,
а не удаление случая. Граница BARO — начало сохранённого окна. Его собственное
разбиение `< start` / `>= start` сохраняется, включая пограничные scrape-точки.

Колонки стабильны: порядок кандидатов из окна, затем cpu/memory/network/traffic_rate.
Результат на уровне метрик проецируется на сервис первым появлением его колонки
(stable dedup), без знания причины и без изменения порядка. Исключённые upstream
константные ряды не дорисовываются. Отсутствие правильного сервиса в выдаче — miss.

## Приёмка и бюджет

1. Проверить pinned HEAD/чистоту используемых upstream-файлов, поддерживаемые
   зависимости, полноту входа, непротиворечивость mapping и отсутствие truth.
2. Один полный прогон 50 случаев. Ошибки остаются в общем знаменателе 50.
   До 30 секунд на вызов; остановка всей серии при техническом зависании,
   не многократные повторения с разными параметрами.
3. Сохранить per-case ранги, source/input SHA256, версии, успехи/ошибки,
   покрытие кандидатов и время. Исходный source не патчить.
4. Accuracy@1/3/5 и MRR; при достаточной совместимости парные разности
   с текущим ансамблем, cluster bootstrap по исходным 25 группам, 10 000,
   seed=20261020. Отказы учитываются как rank=0; не только successful subset.
5. Никакого promotion весов по этой таблице. При слабом/сильном BARO результат
   сохраняется одинаково. При несовместимости фиксировать причину, не нулевую
   «точность алгоритма». Отдельно назвать режим same-case / different modality.

## Почему не остальные прямо сейчас

TraceRCA в pinned реализации требует `methodName/operationName`. В сохранённом
каноническом M14 trace есть service/span/parent/duration/kind/error, но нет имени
операции. Подстановка service вместо operation изменила бы смысл метода.
MicroRank ранее не прошёл ограниченный smoke; многомодальные методы требуют
отдельных производных рядов, которых нет в этом контракте. Их отсутствие не
записывать как поражение конкурента. Не делать новые стенды ради количества строк.

## Отчёт после результата

с текущим ансамблем, существующей эвристикой и BARO, одинаковым N и модальностями,
один абзац условий и вывод без обещания победы. Сохранить исходную таблицу и
назвать post-hoc характер. При несовместимости — корректное описание границ
сравнения, без выдуманных чисел. Не менять формулы/диаграммы/комментарии ради этого.
До результата DOCX не правится. Полная редакция проходит обычную render/Pages QA.
