# Необязательный контекст журналов и событий Loki

Статус: `PROMOTED_BOUNDED_OPTIONAL_CONTEXT`. Проверено с настоящим Loki 3.7.8
и журналами реальных отказов учебного HTTP-сервиса. Это источник наблюдений,
не вход ML-модели и не автоматическое доказательство причины. Не заявляются
рост Accuracy@K, польза LLM или сокращение времени инженера.

## Проверяемая гипотеза

Похожие задержки и количества ошибок могут соответствовать разным механизмам.
Структурированная запись `PermissionDenied` и HTTP 403 даёт другую проверку,
чем `ConnectionRefused` и HTTP 503. Прототип сохраняет это различие и источник;
он не выбирает причину автоматически. Запись о релизе — утверждение источника
о событии, не доказательство причинной связи с инцидентом.

## Подключение к приложению

Интегратор добавляет необязательный объект `context` в уже установленный
профиль. Его содержимое совпадает с примером ниже. `services` сопоставляет
канонические имена кандидатов с меткой источника, `labels` ограничивает
окружение/проект. Ключи `services` — подмножество кандидатов, максимум 20.
Произвольный LogQL, URL или сервис в запрос инженера/LLM не принимаются.

После изменения профиля перезапустите приложение. Менять модель, готовить
JSON-окно или заново рассчитывать baseline ради подключения контекста не нужно:
контекст не участвует в его математическом контракте. Выберите прежние систему
и интервал. В наблюдениях появится раскрываемый блок «Журналы и события».
Источник и отметки времени сохранены в том же снимке расследования.

По умолчанию контекст остаётся локальным. Дополнительный операторский флаг
`"assistant_categories": true` разрешает помощнику только фиксированные
категории и количества (например, PERMISSION_RESPONSE, CONNECTION_REFUSED,
OPERATION_TIMEOUT), при наличии обычного разрешения на передачу агрегатов
этого проекта. Строки, классы исключений, версии, хеши и адреса не передаются
даже с этим флагом. Новые категории требуют пересмотра контракта; неизвестная
ошибка остаётся OTHER_ERROR. Любая категория предлагает проверку, а не диагноз.

## Отдельная проверка оператором

Создайте локальный конфигурационный файл вне Git, например
`.rca-private/loki-probe.json`. Это пример, требующий ваших настоящих меток:

```json
{
  "source_id": "teaching",
  "url": "http://127.0.0.1:3100",
  "service_label": "service_name",
  "services": {"payment": "payment-v1"},
  "labels": {"environment": "local"}
}
```

```bash
.venv/bin/python tools/loki_context_probe.py \
  --config .rca-private/loki-probe.json --service payment \
  --start 1700000000 --end 1700000030
```

Интервал — прошедшее время Unix UTC, начало включается, конец исключается.
Для авторизации есть необязательное поле `token_env`: имя серверной переменной
с Bearer-токеном, не сам токен. Вне loopback авторизация требует HTTPS.
Источник задаёт доверенный оператор, не браузер и не LLM; сетевой доступ
процесса дополнительно ограничивается средствами окружения.

## Контракт и ограничения

- CLI делает один GET `query_range`. Приложение — не более 20 запросов по
  установленному инвентарю (не по ML-рангу), максимум 100 записей суммарно.
  Точные фиксированные метки, без произвольного LogQL.
- Не более часа, 256 KiB на ответ (до 5 MiB на весь batch), 8 KiB на строку; без пагинации,
  повторов и редиректов. Отдельный дочерний процесс ограничивает ожидание
  источника десятью секундами; при превышении завершается только этот процесс.
- Допустимы структурированные `error.type`, `exception.type`, `service.version`,
  ограниченный `event.name` и HTTP-код. Тело сообщения, прочие метки, URL,
  команды инъекции и поля `root_cause`/`fault_type` не выдаются.
- Фильтр полей не гарантирует обезличивание. Даже имя исключения или версия
  могут быть закрытыми. Результат остаётся локальным; автоматической отправки
  LLM нет. В снимок попадают только выбранные локальные поля, не исходное тело.
- Время записи Loki не объявляется истинным временем события. Время чтения
  хранится отдельно. ID и SHA-256 исходной строки связывают выбранные поля
  с записью; SHA-256 не даёт права раскрывать её содержимое.
- `available` означает пригодный ответ, не полное покрытие. При достижении
  лимита — `truncated`; пустой ответ не подтверждает здоровье сервиса.
  Retention, sampling, задержки доставки и полнота остаются неизвестными.
- Неструктурированные строки учитываются как пропущенные, не интерпретируются
  свободным текстом. Неверный scope, предупреждения сервера и ошибки источника
  закрываются явным `unavailable`, а не нормальным отсутствием ошибок.

Отказ, усечение и недоступность projection не ломают основной рейтинг;
результат с неполным контекстом не переиспользуется кэшем как свежий полный.
Жёсткое ожидание дополнительного источника — 10 секунд плюс завершение своего
worker. Ожидание присоединившегося запроса расширено до 140 секунд с учётом
прежнего 120-секундного бюджета основных источников; UI timeout — 150 секунд.

Пилот дал различающие признаки отказа доступа и соединения при общем внешнем
503; таймаут частично различим уже по задержке. Контроль постороннего релиза
не включён в scope. Подробности и ограничения: [приёмка](LOKI_ACCEPTANCE.md).
В новой установке интегратор всё равно проверяет свои labels, clocks,
retention, sampling, права и происхождение записей. Не подключайте потоки
контроллера инъекций, разметку опыта или журналы другой системы.
Установка Loki/агента сбора и настройка прав остаются в контуре владельца
источника; продукт не читает Docker socket и не устанавливает Loki сам.
