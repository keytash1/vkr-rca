# Диагностическое приложение: необязательный автономный комплект

Основной источник кода и обновлений — GitHub-репозиторий `keytash1/vkr-rca`. Этот ZIP — дополнительный снимок для **одной уже настроенной системы**. Он содержит вычислительный модуль, зафиксированные модели, веб-приложение и её профиль; в нём нет разметки инцидентов и корпуса независимого эксперимента. Имена сервисов и адреса источников определяет установленный профиль.

## Установка и запуск

Нужен Python 3.12 или новее. Из распакованного каталога установите зависимости в отдельное виртуальное окружение:

```bash
python3 verify_bundle.py --root .
python3 -m venv .venv
.venv/bin/python -m pip install ./ml
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/server.py --root .
```

Откройте показанный адрес на том же компьютере. Пользователь выбирает систему и интервал известного инцидента; файл диагностического окна не нужен. Источники должны быть доступны с компьютера приложения по адресам профиля. Сервер по умолчанию слушает только `127.0.0.1` и не предоставляет аутентификацию либо TLS; его нельзя открывать в общей сети без отдельного защищающего прокси.

В профиле должны быть указаны запросы Prometheus `query_range`, совместимый поиск трассировок Jaeger, полный список кандидатов и источник интенсивности запросов. Запрос каждой метрической семьи должен возвращать не более одного ряда на сервис и момент времени. Для нового подключения предусмотрен стабильный QueryService v3 (`jaeger-v3-json`); прежний `jaeger-http-json` использует внутренний JSON API веб-интерфейса и требует проверки совместимости конкретной установки. Переключения после ошибки нет. Программа не дообучает модели и не меняет наблюдаемую систему.

## Проверка комплекта

`bundle-manifest.json` содержит SHA-256 каждого вложенного файла; команда `verify_bundle.py` проверяет состав и суммы **до** установки зависимостей. Для подтверждения происхождения архива его SHA-256 передают получателю по доверенному каналу: внутренний манифест не является цифровой подписью. Веса пяти итоговых моделей дополнительно проверяются при запуске по зафиксированному манифесту. Результат — полный рейтинг для проверки инженером, а не вероятность или доказанная причина отказа.

Подготовка нового профиля и здорового базового состояния выполняется в исходном репозитории командой `cmd/thesis_demo/profile_setup.py` до сборки комплекта. Архив создаётся `deploy/product/build_bundle.py --profile deploy/profiles/<id>.json --output <archive.zip>`.
