# Совместимость и границы установки

Переносимость здесь означает подключение другой системы профилем без изменения
диагностического кода. Она не отменяет настройку источников, единиц, алиасов,
инвентаря сервисов и здорового периода. Инженер использует готовое подключение;
эту настройку выполняет интегратор.

## Проверенные варианты

| Вариант | Что проверено | Что из этого не следует |
|---|---|---|
| Linux aarch64, Python 3.12.15 в Docker | Реальные источники Petclinic, новый baseline, рейтинг, workspace, повтор/перечитывание, короткий soak и restart | Не сертификация всех Linux/архитектур и не длительный SLA |
| macOS ARM64, Python 3.14.5, новое venv | Чистый исходный состав, установка зависимостей, самодостаточные тесты, новый baseline, живой браузерный путь и карточка | На машине уже установлен OpenMP; это не установка на пустую macOS |
| Native-подключение необязательного провайдера | Собственный официальный вход, каталог моделей и предыдущие реальные ограниченные вызовы | Наличие модели не подтверждает остаток лимита или качество помощника |

Проверены конкретные сборки, а не все версии Python `>=3.12`. Фактические версии,
hash состава и протокол проверки фиксируются для каждого выпуска отдельно.
Для новой платформы предпочтителен контейнер; несовместимая wheel/системная
библиотека должна выявляться до рабочего запроса.

## Системные зависимости и файловая система

- Linux-образ устанавливает `libgomp1`. Native XGBoost на macOS требует доступного
  OpenMP runtime; установка Python-пакета сама по себе не устанавливает все
  системные библиотеки. После установки выполните импорт XGBoost и запуск
  приложения до настройки пользовательского подключения.
- Активация профиля, workspace и OAuth refresh используют POSIX `fcntl` locks.
  Native Windows этим выпуском не поддерживается. Применяйте Linux-контейнер
  или отдельно проверенное Linux-окружение; WSL не объявляется проверенным
  только из-за наличия Docker.
- Приватные каталоги должны принадлежать UID процесса, иметь режим 0700,
  приватные файлы — 0600. Нельзя обходить проверку владельца запуском от root
  или разрешением чтения всем пользователям.
- Виртуализация bind mounts может менять видимый UID: это обнаружено с Colima.
  Если host-каталог авторизации внутри контейнера отображается как root,
  подключение безопасно отклоняется. Этот bind-вариант не принят для live LLM;
  не копируйте rotating credentials в две независимые установки. Native-путь
  остаётся отдельным проверенным вариантом.

## Сеть и эксплуатация

### Ошибки трассировок разных инструментаторов

Jaeger HTTP JSON нормализует `http.response.status_code` и `otel.status_code`
в тот же канонический признак ошибки, что и прежний `http.status_code`.
Поддерживается явно типизированное строковое сообщение `error` от Zipkin,
включая его сочетание с `error=true` после преобразования Collector/Jaeger.
В OTLP/v3 строка `error` также трактуется как сообщение об ошибке. Текст
сообщения отбрасывается: в диагностическое ядро передаётся только boolean.
Boolean `false` остаётся false; нетипизированная строка вместо флага
и противоречивые HTTP-алиасы отклоняются, не превращаются в нормальный ноль.
Основание — [правила Zipkin-преобразования OpenTelemetry](https://opentelemetry.io/docs/specs/otel/trace/sdk_exporters/zipkin/#status).

Это исправление совместимости декодера, не переобучение модели. Проверено
на сохранённых ответах настоящего Spring Petclinic → Collector → Jaeger 2.20.0:
восстановлены шесть ранее отвергнутых окон с ошибками; успешные канонические
окна сохранились точно. Оно не гарантирует совместимость любого инструментария
или полноту трассировок при пропущенной инструментации.

### Ограничения локального запуска

Сервер рассчитан на одну доверенную локальную установку. Публикация порта только
на loopback обязательна для workspace; встроенных пользователей организаций,
TLS и межкомандных ACL нет. Контейнер не требует Docker socket. Доступ к
Prometheus/Jaeger проверяется из самого места запуска, не только из браузера
интегратора. Источники должны соответствовать профилю и удерживать нужный интервал.

Один процесс выполняет один анализ; одинаковый повтор может присоединиться
в пределах установленного лимита. Для помощника — одна выполняемая и одна
ожидающая задача. Это ограничения продукта, не измеренная пропускная способность.
Короткий soak не заменяет проверку нагрузки и retention в конкретной установке.

Отказ LLM не выключает рейтинг и сохранённые наблюдения. Неизвестный расход
прерванного потока сохраняется как UNKNOWN, а не как ноль; автоматическая
оценочная серия при таком событии останавливается. Дополнительных покупок,
платного fallback или автоматического повторения прерванного вызова нет.

## Проверка до передачи пользователю

1. Сверить состав/суммы поставки и версии окружения; не переносить `.venv`
   с другой машины.
2. Пройти процедуру `inspect → prepare → activate` из руководства подключения
   на реальных источниках, подтвердить единицы, scope, инвентарь и здоровый период.
3. Запросить известный прошедший интервал, сверить значения с источниками;
   проверить отсутствие данных и отказ источника отдельно от здорового ответа.
4. Сохранить и повторно открыть карточку; после restart убедиться, что снимок
   не заменён новым чтением источников.
5. Включать внешнюю модель только для разрешённых проектов, после отдельной
   авторизации и проверки передачи данных. Не считать наличие API или валидного
   JSON доказательством полезности её выводов.
