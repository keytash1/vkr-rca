# Контракты RCA Workbench

## Граница установки

Одна trusted-local установка, один доверенный владелец, несколько явно
настроенных профилей. UI, API, неизменяемый ранжировщик и карточки переносятся
вместе; разовая настройка источников/baseline принадлежит интегратору.
Инцидент уже обнаружен внешним мониторингом или человеком. Программа не
является автоматическим детектором, системой multi-tenant ACL или исполнителем
ремонта. Выход ранжировщика — порядок проверки, не вероятность причины.

## Исполняемые границы

| Граница | Реализация | Контракт |
|---|---|---|
| Профиль и подключение | profile_contract, profile_onboarding, profile_setup | Подтверждённый инвентарь, смысл/единицы/агрегация метрик, scoped адреса, подготовка неизменной версии baseline и явная активация/откат. |
| Источники → внутреннее окно | live_sources, trace_adapters | Prometheus query/query_range и поддерживаемые Jaeger HTTP JSON API. Неизвестные метки/неверные единицы не становятся молча корректными; пропуск не равен нулю. |
| Окно → ранжирование | profile_runtime, ml/rca_ml | Зафиксированные признаки/веса и baseline профиля. Сеть, credentials, текст LLM, gold и ручной вывод не входят в расчёт. |
| Наблюдения и воспроизведение | evidence_catalog, trace_evidence, workspace_store | Исходные значения, единицы, временные группы, ID фактов, качество источника и immutable snapshot с версиями/хэшами. История открывается без нового сбора. |
| Прикладной API и карточка | server, workspace_http, investigations | Профиль+интервал, полный результат, session/Origin/CSRF, revision/idempotency, запись проверки человеком, локальный JSON/Markdown экспорт. |
| Необязательный помощник | assistant_privacy/context, tools, runner/workflow, supervisor/provider | Только разрешённая псевдонимизированная проекция выбранного снимка, bounded read-only tools, одобренные scoped runbooks и структурный ответ. |

Это реальные Python-модули, а не обещанный универсальный plugin SDK. Новый
протокол источника требует отдельного адаптера, контрактных тестов и настоящей
приёмки подключения. Замена только профиля возможна в пределах поддерживаемых
API/смысловых соответствий. Произвольный сайт без телеметрии не является
подключённой системой. Docker socket и доступ к контейнерам программе не нужны.
Фактический смысл PromQL-метрики подтверждает интегратор: источник не позволяет
программе вывести правильную единицу или агрегацию из одного имени метрики.

## Неподменяемые состояния

- Ошибка чтения обязательных метрик — ошибка анализа без правдоподобного
  рейтинга. Недоступность трасс отличима от отсутствия спанов в интервале.
- Наблюдаемое нулевое значение с покрытием, NOT_OBSERVED и UNAVAILABLE —
  разные состояния. Sampling/retention не предполагаются известными.
- Повторный полный запрос может кратко использовать memory cache. Force
  refresh создаёт новый результат, не переписывает старое расследование.
- Профиль/baseline привязаны семантическим контрактом и хэшами. Изменение
  запроса, кандидатов или единиц не подменяет активную совместимую версию.
- Подтверждённая человеком причина, ML-кандидат и гипотеза LLM раздельны.
  Отметка review связана с SHA содержимого карточки, не подтверждает все меры.
- Мера имеет отдельно план и результат проверки. Предложение LLM не назначает
  владельца/срок, не выполняется и не становится verified автоматически.

## Граница внешней передачи

Разрешение задаёт оператор для каждого profile ID. Вопрос может быть
чувствительным — секреты/неразрешённые материалы туда не вводят. В outbound
нет исходных имён, URL источников, сырых tags/span IDs, gold и ручной карточки;
псевдонимы не гарантируют анонимность. До двух прежних ответов входят как
недоверенная история, не как новые факты. Режим E для сравнения не получает
рейтинг ни напрямую, ни через историю/tools.

Шесть tools ограничены выбранным снимком: факты сервиса, сравнение метрики с
baseline, числовые примеры спанов, наблюдаемые зависимости, поиск одобренных
runbooks и выбор целых временных групп. Нет shell, файловых путей, произвольных
URL/PromQL, другого проекта и изменения сервисов. Текст runbook — рекомендация,
не доказательство. Внутренний tool output сам не подтверждает причину.

Supervisor ограничивает локальный worker по времени; число calls/tools/steps
и usage учитываются. Для длинного уточнения заранее сохраняется место для
итога; инструменты могут быть закрыты до первого вызова, и это явно отмечается.
Нет обещания жёсткого remote generation cap. Отмена/обрыв могут оставить
неизвестный расход, он не заменяется нулём. B, исходные факты и карточка
работают при отказе провайдера. Предел 24h jobs не является ценой токена.

## Принятые решения и альтернативы

1. **Приватная SQLite вместо отдельной БД/Redis.** Достаточна для локального
   ограниченного объёма и transactional revisions/reservations. Retention,
   размеры и число записей ограничены. Не обещает горизонтальное масштабирование.
2. **Docker named volume вместо macOS private bind по умолчанию.** Владелец
   10001/0700 берётся из image при создании нового тома; процесс не root и
   не исправляет владельца чужих данных при старте. Для native каталог владельца
   остаётся 0700, файлы 0600. Обновление/backup описаны в WORKSPACE.
3. **Отдельный read-only помощник вместо агента с OS-доступом.** Ранг не меняется,
   недостоверный/неполный ответ не заменяет детерминированный результат.
   Качество определяется отдельно по гипотезам/фактам/следующим проверкам.
4. **Разделение research и product.** В продуктовой поставке нет fault controls,
   oracle, экспериментального корпуса или обязательного Astronomy Shop.
   Контролируемые учебные опыты и оценочные скрипты принадлежат исследовательской
   истории, не рабочим инструментам LLM.

Логи, релизы/изменения и события Docker/Kubernetes не заявлены подключёнными
источниками этого выпуска. Их отдельная исследовательская итерация не меняет
вход обученного ранжировщика без нового протокола. Внедрение в общей сети
потребует отдельной аутентификации, TLS и egress policy; публикация trusted-local
порта не заменяет эти меры.
