# Локальное рабочее пространство

## Меры и обзор расследований

Экспорт доступен в двух форматах: JSON сохраняет полный снимок и историю,
Markdown — читаемую сводку карточки для передачи команде. Перед выгрузкой
сохраните правки. В Markdown раздельны план и результат проверки, состояние
черновика, причины, меры и версии/контрольные суммы. Свободный текст экранируется
как литерал, а не исполняется как HTML/картинка/команда. Программа только сохраняет
локальный файл; сама не публикует его и не создаёт тикет. Секреты и неразрешённые
данные нельзя включать в передаваемую командой сводку.

«Отметить проверку карточки» относится только к сохранённому содержанию и требует
владельца расследования и вывода (он может оставаться неразрешённым). Сервер
вычисляет SHA-256 записи и время; клиент/LLM не могут прислать отметку вместо
проверки. Изменение содержания сбрасывает её, сохранение того же содержания
сохраняет отметку. Устаревшая ревизия отклоняется. Это локальная отметка проверки,
не цифровая подпись, не утверждение всех причин и не проверка эффекта всех мер.
API: `POST /api/v2/investigations/{id}/review` с `expected_revision` и обычной
защитой session/Origin/CSRF. Неотмеченный черновик можно экспортировать как черновик.

Помощник может предложить до двух условных мер: смягчение последствий,
исправление механизма или снижение риска повтора. Предложение содержит сервис,
основание/ссылки на факты и план проверки эффекта. «Добавить в черновик мер»
меняет только локальный черновик; требуется отдельное сохранение карточки.
LLM не назначает ответственного/срок, не выполняет изменение и не подтверждает
эффект. При недостатке наблюдений список может быть пустым.

В карточке раздельны назначение меры, основание, план проверки, фактический
результат и внешний тикет. Для принятой в работу меры нужны ответственный и
срок; «эффект проверен/не подтверждён» требует записанного результата. Старые
карточки/ответы читаются без переписывания исходных записей.

Есть необязательные владелец расследования, номер инцидента и категория.
История фильтруется по ID системы, сервису в человеческих гипотезах/мерах,
категории, состоянию мер и дате создания карточки (не дате инцидента).
При сочетании сервиса и состояния ищется мера именно этого сервиса.
Фильтрация выполняется до ограничения выдачи (по умолчанию 30, максимум 100).
Просрочены открытые planned/in_progress/verification_pending со сроком в
прошлом; проверенные меры сюда не входят. Гипотезы и подтверждённые инженером
сервисы раздельны. История ограничена retention: отсутствие записи не доказывает
отсутствие повторений. Автоматического поиска похожих причин/измеренного MTTR нет.

API: `GET /api/v2/investigations?project=...&service=...&category=...&after=...&before=...&action_status=...&limit=...`.
`after/before` — Unix seconds создания карточки, границы включительные.
Допустимые action_status перечислены в OpenAPI; `overdue` — открытые
просроченные меры. Повторные/неизвестные/пустые фильтры отвергаются.
Копирование предложения не меняет исходный рейтинг или immutable snapshot.

Необязательный состав комплекта указан в `bundle-manifest.json`: `workspace`
добавляет карточки и сохранённые наблюдения; `assistant_code` — код подключения
помощника. Ни один вариант не включает учётные данные или разрешение передачи.
Полный рейтинг и карточки работают без LLM.

## Сначала — без внешней передачи

После установки по README запустите из каталога комплекта:

```bash
PYTHONPATH=ml:cmd/thesis_demo .venv/bin/python cmd/thesis_demo/server.py \
  --root . --workspace-dir .rca-private/workspace --port 18100
```

Только локальная установка для одного доверенного пользователя, не сервер
аутентификации для нескольких компаний. Не публикуйте порт в общей сети.
В интерфейсе: система и интервал → рейтинг → «Создать карточку». Открытая снова
карточка использует исходный снимок, не запрашивает источники заново. Новое
перечитывание источников — новый результат; старое расследование не подменяется.

Снимки и карточки хранятся в приватной SQLite до 7 дней; параметр
`--workspace-retention-days` допускает 1–30 дней. Экспортируйте нужную карточку
до истечения срока. Удаление снимка удаляет связанные расследования и шаги;
это логическое удаление, не гарантия физического стирания SSD/резервных копий.
Непривязанный к содержимому счётчик резервирования LLM-запусков живёт до
24 часов: удаление карточки не сбрасывает предел использования помощника.

## Помощник

Нужен состав `assistant_code` и отдельно установленное окружение:

```bash
python3 -m venv .venv-assistant
.venv-assistant/bin/python -m pip install -r requirements-assistant.txt
PYTHONPATH=cmd/thesis_demo .venv-assistant/bin/python cmd/thesis_demo/assistant_auth.py --help
```

Авторизация — отдельный официальный вход владельца установки. Не копируйте
чужую папку авторизации и не отправляйте токены в чат. Доступность модели и
право использовать подписку проверяются отдельно. Автоматических покупок и
переключения на платный API нет.

Администратор явно задаёт `--assistant-python`, `--assistant-state-dir`,
`--assistant-model` и `--allow-assistant-profile ID` для каждого разрешённого
профиля. До включения он должен разрешить передачу именно его агрегатов в
OpenAI. Снимки очищаются от произвольных тегов и исходных имён, но это не
гарантия анонимности: неизвестные/секретные данные не следует передавать.
Корпоративные runbooks не входят в комплект; их права проверяются отдельно.

Одна задача выполняется, одна ожидает. Отмена останавливает локальный worker;
прекращение генерации у провайдера и остаточный расход могут оставаться
неизвестными. После перезапуска прерванные задачи не отправляются повторно.
LLM предлагает проверки, не исполняет команды и не подтверждает причину.

`--assistant-daily-jobs` задаёт локальный предел новых LLM-заданий за скользящие
24 часа (по умолчанию 20, допустимо 1–200). Резервирование транзакционное,
переживает restart; повтор с тем же idempotency key не тратит второй слот.
Уточнение — новое задание. Отменённый/прерванный запуск также занимает слот,
даже если фактический usage не получен. Это консервативный лимит заданий,
не цена токенов, не остаток тарифа ChatGPT и не жёсткий предел удалённой генерации.
Наблюдения, ML-рейтинг и карточки B доступны после исчерпания. До 10 шагов
расследования — отдельный предел; счётчик 24 часов общий для всей установки.
При первой миграции учитываются прежние LLM-шаги за этот период. Таблица
хранит только непривязанные к тексту ключи/время, не копию удалённой карточки.
Перед обновлением остановите старый процесс и сделайте приватную резервную
копию SQLite; миграция схемы 1/2 → 3 при занятом worker lock отклоняется.
Новая схема несовместима со старым writer: для отката нужен старый код вместе
с его резервной базой, а не попытка открыть схему 3 прежней версией.

## Контейнер и границы подключения

В исходном продуктовом комплекте предусмотрены три явных build targets:
`runtime` (только основной анализ), `workspace` (сохранение/карточки без
провайдера) и `assistant` (добавлены optional-зависимости и worker).
Последний target по умолчанию остаётся минимальным, LLM не включается скрыто.
Профили и baseline подключаются read-only, приватное рабочее пространство —
отдельным writable volume. Docker socket продукту не нужен и не монтируется.

Для исходного репозитория подготовлены `deploy/product/compose.workspace.yml`
и явный optional override `compose.assistant.yml`. Перед запуском задайте
абсолютный `RCA_PROFILES_DIR` и имя доступной источникам сети
`RCA_SOURCE_NETWORK`. Профили/baseline должны читаться UID 10001 контейнера;
токены источников передаются через защищённую конфигурацию окружения, не файлы
публичных профилей. Для несекретных профилей допустимы каталоги 0755/файлы 0644.
Не меняйте права на произвольных каталогах с секретами ради запуска.

Рабочее пространство использует отдельный Docker-managed named volume
`RCA_WORKSPACE_VOLUME` (по умолчанию `rca-workbench-workspace`). Новый том
получает владельца 10001:10001 и режим 0700 из образа. Процесс всегда non-root;
проверки владельца/прав не отключаются. Bind-mount приватной базы с macOS/Colima
не рекомендуется: отображение владельца точки монтирования может измениться
после restart. Установку с прежним bind-mount не конвертируйте на месте: остановите
writer, сохраните приватную резервную копию, отдельно проверьте восстановление
в новом томе. Старые данные автоматически не переносятся и не удаляются.
Не используйте один том одновременно для двух работающих экземпляров.
`docker compose down` сохраняет том; `down -v` удаляет его вместе с карточками.
Без LLM:

```bash
docker compose -f deploy/product/compose.workspace.yml up -d --build
```

Для optional-варианта дополнительно нужны `RCA_ASSISTANT_STATE_DIR`,
`RCA_RUNBOOK_FILE` и явно одобренный `RCA_ASSISTANT_PROFILE`. Авторизация должна
быть выполнена владельцем отдельно; пароль/токены в Compose не записываются:

```bash
docker compose -f deploy/product/compose.workspace.yml \
  -f deploy/product/compose.assistant.yml up -d --build
```

Само наличие runbook-файла не заменяет разрешение его передавать. Для нескольких
разрешённых проектов добавьте отдельные `--allow-assistant-profile` в локальную
конфигурацию; wildcard «все проекты» не поддерживается. Assistant image содержит
проверенный публичный словарь токенизатора, его не нужно загружать при запросе.

Порт публикуйте только на loopback хоста. При публикации `18100` контейнера,
например на `127.0.0.1:18100`, серверу workspace явно передаётся
`--workspace-origin http://127.0.0.1:18100`. Заголовки forwarded не заменяют
это доверенное значение. Параметр `--unsafe-public` нужен для bind внутри
контейнера и не делает приложение защищённым многопользовательским сервисом.
Для выхода в общую сеть требуются отдельные authentication/TLS/egress policy;
публичная публикация trusted-local рабочего пространства не поддерживается.

`GET /healthz` — отдельная нечувствительная проверка готовности ядра для
контейнера: только `ready`/`not_configured`, без cookie, списка профилей,
содержимого карточек или обращения к источникам. Он работает на внутреннем
порту независимо от browser origin. `/api/health` сохраняет обычную проверку
Host/Origin и не заменяет проверку доступности телеметрии.

Авторизацию монтируют отдельно от образа в приватный каталог владельца.
Каталог должен быть доступен для безопасного обновления токена и lock-файла;
не включайте его в image layers, Git или экспорт расследования. OAuth-вход
владелец выполняет на своей установке. Копирование авторизации одного
пользователя другим не является способом лицензировать поставку.

Повторный одинаковый полный запрос кратко переиспользуется в памяти; сервер
показывает время исходного сбора и признак reuse. «Перечитать источники»
создаёт новый результат. Неполные/неуспешные ответы не кэшируются как нормальные.
Отсутствие трасс в старом интервале может означать retention/sampling, а не
здоровье сервиса. Сохранённая карточка остаётся привязана к прежнему каталогу.

## Обновление и откат

Перед обновлением остановите процесс, экспортируйте нужные карточки и сделайте
локальную резервную копию приватного volume с его ограничениями доступа.
Сохраняйте принятую версию кода/image digest и версии профиля/baseline. Новая
версия запускается на копии volume; проверяются история, снимок и основной
анализ без LLM. Нельзя одновременно запускать два manager на одном volume.

Схема workspace v2 умеет читать и мигрировать v1. Обратная совместимость старого
бинарника с новой SQLite не обещается: откат — принятый код **и соответствующая
дообновлённая копия volume**, а не принудительное открытие новой БД старым кодом.
Повреждённые/просроченные данные не пересоздаются незаметным внешним вызовом.
